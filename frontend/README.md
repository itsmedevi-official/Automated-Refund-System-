# SmartEscrow - React frontend

Single-page DApp for the SmartEscrow contract (thesis Chapters 3-5). It renders one
dashboard per role - buyer, seller, delivery agent, escrow agent - plus a deal explorer,
a deal detail page with the whole lifecycle, and an owner-only settings page.

The app talks to the **local Hardhat chain only**. There is no real money involved.

## Stack

| Layer | Choice |
|---|---|
| Build tool | Vite 6 + `@vitejs/plugin-react` |
| UI | React 19, React Router 7, plain CSS (`src/index.css`) |
| Chain access | `ethers` v6 with the browser provider injected by MetaMask |
| Contract ABI | generated file `src/contracts/SmartEscrow.json` |
| Deployment info | generated file `src/config.json` |

Both generated files are written by `backend/scripts/deploy.js`, so the frontend never
reads anything outside its own root (no `server.fs.allow` tricks).

## Prerequisites

- Node.js 18+
- `npm install` inside `frontend/`
- A running backend: local chain, deployed contract and (optionally) seeded demo deals

## Quick start

```bash
# terminal 1 - local chain
cd backend
npx hardhat node

# terminal 2 - deploy + seed
cd backend
npx hardhat run scripts/deploy.js --network localhost
npx hardhat run scripts/seed-demo.js --network localhost

# terminal 3 - the app
cd frontend
npm install      # first time only
npm run dev      # http://localhost:5173
```

`deploy.js` rewrites `src/config.json` and `src/contracts/SmartEscrow.json`, so a plain
page refresh is enough after redeploying (Vite hot-reloads the JSON modules as well).

Read-only pages (home, explorer, deal details) work without a wallet because they use a
`JsonRpcProvider` against `VITE_RPC_URL` / `config.rpcUrl`. Every transaction, however,
needs MetaMask; the app refuses to submit if the wallet is on another chain.

## Routes

| Route | Page | Wallet |
|---|---|---|
| `/` | Home - live contract parameters, lifecycle explanation | optional |
| `/buyer` | Buyer dashboard + "New deal" | required |
| `/buyer/new` | Create a deal (amount, seller, delivery agent, optional location) | required |
| `/seller` | Seller dashboard (locked vs. received funds) | required |
| `/delivery` | Delivery agent dashboard (OTP to generate / deliveries to verify) | required |
| `/agent` | Escrow agent dashboard (escalated queue + open disputes) | required |
| `/deals` | Explorer with search and state filter | optional |
| `/deals/:dealId` | Deal details: timeline, role-specific actions, OTP panel | optional |
| `/settings` | Contract parameters + deployment info (owner-only writes) | required |
| `/explorer` | Redirect to `/deals` | - |
| `*` | Not found | - |

## Walkthrough of the thesis flow

1. **Buyer** - `/buyer/new`: pick seller and delivery agent, lock the amount, optionally
   store the delivery position (`setBuyerLocation`, micro-degrees).
2. **Delivery agent** - `/delivery` → open the deal → *Generate OTP*. The contract emits
   `OTPGenerated(dealId, otp, at)` and stores only `keccak256(otp)`.
3. **Buyer** - the deal page shows the OTP (read from the event, buyer view only) and hands
   it to the agent at hand-over.
4. **Delivery agent** - enter the 4 digits, capture the GPS position, *Verify delivery*.
   The contract computes the distance with `GeoUtils` and starts the dispute window.
5. **Nobody disputes** - after the window the deal page (or `keeper.js`) offers
   *Release funds*; the seller is paid and `FundsReleased` records the distance.
6. **Buyer disputes** - `/deals/:id` → reason → *Open dispute*, then
   *Run automatic resolution*: within the threshold the seller is paid, otherwise the buyer
   is refunded. Missing evidence (no OTP, no buyer location) escalates the case.
7. **Escrow agent** - `/agent` lists the escalated queue; select *Refund the buyer* or
   *Pay the seller*, add a note, submit. Resolved deals leave the queue.

## Troubleshooting

- **"No contract address found in src/config.json"** - the backend has not been deployed
  against the running chain yet (or `npx hardhat node` was restarted, which wipes state).
  Re-run `deploy.js` (and `seed-demo.js`).
- **Empty dashboards** - the connected account really has no deal in that role. Use the
  explorer, or seed the demo deals with `#1` as buyer.
- **`could not decode result data` / stale data** - the configured address points to a
  contract from an older chain instance; redeploy.
- **"Invalid OTP"** - make sure the buyer's page shows the OTP generated *for this deal*;
  the delivery dashboard never displays it by design.
- **MetaMask shows old nonces / balances** - clear the account's activity data
  (Settings → Advanced) or restart the node and redeploy.
- **Wrong network banner** - the `WalletButton` offers a one-click switch to chain 31337.
